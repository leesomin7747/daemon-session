# 두 사람의 펫 온라인 사무실 MVP 기획

작성일: 2026-10-16

승인: 2026-10-16 사용자가 본문과 보완한 가정을 수용하고 구현 계획 작성을 요청했다.

새벽에 각자 개발하거나 과제하는 두 사람이, 할 말이 없어도 함께 있다는 느낌을 받는 데스크톱 서비스다. 작업창 아래의 펫으로 짧은 장난과 챙김을 주고받고, 서로 집중할 시간도 존중한다. 제품 이름은 아직 정하지 않았다. 목업의 ‘같은 세션의 밤’은 시안을 설명하는 제목이다.

아래 제품 방향과 상호작용은 대화와 목업을 통해 확인했다. ‘작성자 판단’으로 표시한 항목은 계획 수립을 위한 제안이며, 사용자가 따로 선택한 사항은 아니다. 기술 스택과 배포 방식은 구현 계획에서 결정한다.

## 실제 사용 순간과 핵심 가치

첫 사용자는 새벽 작업이 잦은 개발자 겸 대학생과 같은 분야에서 일하는 남자친구다. 같은 프로젝트의 친구와도 사용할 수 있지만, 한 세션의 참여자는 두 명이다.

지금은 디스코드나 릴스를 보내 대화한다. 그러나 말을 걸고 싶은데 보낼 소재가 없거나, 대화가 끝난 뒤 다시 심심해지는 순간이 있다. 이 서비스는 말없이 함께 머무는 시간 자체에 존재감을 주고, 몇 초의 상호작용으로 기분을 환기한다.

핵심 가치는 다음과 같다.

- 할 말을 준비하거나 계속 대화하지 않아도 함께 있을 수 있다.
- 짧은 장난을 두 사람이 같은 장면으로 경험하고 웃을 수 있다.
- 커피, 에너지음료, 담요, 쪽지로 작은 관심을 표현할 수 있다.
- 상대의 작업과 집중을 존중하고 즉각적인 답장을 요구하지 않는다.

성공 기준 제안: 처음의 신기함이 지난 뒤에도 작업할 때 자발적으로 켜두며, 집중을 해치지 않으면서 동행감을 느끼는지 실제 두 사람의 사용으로 확인한다. 사용 시간, 장난 횟수 등을 경쟁 점수로 만들지 않는다.

## 플랫폼과 지원 범위

첫 지원 목표는 사용자의 macOS와 남자친구의 Linux 환경이다. 전달받은 환경은 EndeavourOS x86_64, KDE Plasma 6.7.5, KWin Wayland다. Windows와 다른 Linux 데스크톱은 이후 확장 후보다.

실제 OS 오버레이는 아직 검증하지 않았다. KDE Plasma는 Layer Shell을 지원하는 환경에 해당한다. 이는 구현 경로를 검토할 근거이며, 현재 목업이 네이티브 오버레이 지원을 입증한 것은 아니다. Electron의 일반 창 API만으로는 Wayland의 항상 위 표시와 위치 지정 요구를 충족하지 못하므로, 프레임워크 선정 전에 해당 환경에서 작동하는 경로를 확인해야 한다.

참고 자료:

- [GTK4 Layer Shell 지원 환경](https://github.com/wmww/gtk4-layer-shell#supported-desktops)
- [Electron BrowserWindow의 플랫폼 제약](https://www.electronjs.org/docs/latest/api/browser-window)

작성자 판단: MVP는 각 컴퓨터의 한 디스플레이 안에서 하단 오버레이를 제공하는 범위로 시작한다. 여러 디스플레이 사이를 이동하는 펫이나 모든 전체 화면 앱 위의 표시 보장은 초기 범위에 넣지 않는다. 일반 작업창 위에서의 표시, 펫 바깥 영역의 클릭 통과, 작업창의 키보드 포커스 보존, 화면 배율 대응은 기술 검증에 포함한다. 남자친구의 전달받은 화면 배율은 125%다.

## 세션과 존재감

두 사람은 한 번 서로 연결한다. 이후에는 둘 다 앱을 켰을 때 자동으로 같은 세션에 접속한다. 매번 방을 만들거나 입장 코드를 다시 입력하게 하지 않는다. 최초 연결 수단은 구현자가 선택하되, 서로 동의한 비공개 일대일 연결과 재접속 가능성을 충족해야 한다.

동시에 접속하면 각자의 화면에 두 펫이 나타난다. 친구가 offline일 때도 사용자가 원하면 자기 펫을 띄워둘 수 있다. 상대의 부재를 실제 온라인 상태와 구별할 수 있어야 한다. 컴퓨터 사용량이나 코딩 내용을 자동으로 읽어 상태를 추정하는 기능은 포함하지 않는다.

작성자 판단: 일시적인 네트워크 끊김과 재접속은 실제 퇴장과 구분해 처리한다. 정확한 재접속 유예 시간과 중복 이벤트 방지 방법은 구현자가 결정한다. 자동 재접속으로 장난이나 쪽지가 중복 실행되어서는 안 된다.

## 화면과 기본 동작

배경은 사용자의 실제 작업 화면이고, 펫과 필요한 소품만 화면 하단의 투명 오버레이에 놓인다. 목업에 보이는 코드 편집기는 실제 작업창을 대신한 시뮬레이션 배경이다.

평소 펫은 하단에서 좌우로 가볍게 움직인다. 펫을 클릭하면 WIP를 볼 수 있다. 자기 WIP는 수정하고 친구 WIP는 읽는다. 장난과 선물은 별도의 행동 선택으로 실행해 WIP 클릭과 충돌하지 않게 한다. 실제 행동 선택 메뉴의 배치는 구현자가 목업의 크기와 분위기를 바탕으로 정한다. 목업 아래의 ‘보내는 쪽’ 선택기는 두 사용자를 한 탭에서 체험하기 위한 도구이며 제품 기능이 아니다.

두 화면에는 같은 대상에게 같은 행동과 같은 말풍선이 보인다. 문구를 각 클라이언트가 따로 추첨해서 서로 다르게 보이게 하지 않는다. 화면 해상도가 달라도 같은 사건과 상대적 배치를 경험할 수 있도록 위치를 표현한다. 밀리초 단위의 완전한 동시 재생은 요구하지 않으며, 눈에 띄는 순서 불일치나 서로 다른 최종 상태를 피해야 한다.

## 장난과 선물

한 번 누르면 짧은 연출이 펼쳐진다. 사용자가 계속 마우스로 조작하는 미니게임은 아니다.

| 행동 | 연출 방향 | busy 중 처리 |
| --- | --- | --- |
| ping 보내기 | 가볍게 건드리거나 펫이 짧게 반응한다 | 실행하지 않는다 |
| 밧줄 끌기 | 친구 펫이 버티다가 끌려온다 | 실행하지 않는다 |
| 간식으로 꼬시기 | 간식을 바라보며 친구 펫이 따라온다 | 실행하지 않는다 |
| 담요 덮기 | 담요 속에 들어갔다가 귀나 눈을 내민다 | 실행하지 않는다 |
| 종이비행기 | 친구 펫에게 도착하고 짧고 우스운 반응을 만든다 | 실행하지 않는다 |
| 커피 건네기 | 커피를 마시고 눈이 번쩍 뜨이는 반응을 한다 | 옆에 선물로 쌓는다 |
| 에너지음료 | 발을 동동 구르는 등 잠깐 활발해진다 | 옆에 선물로 쌓는다 |

밧줄 끌기와 간식으로 꼬시기는 도착한 자리를 새 위치로 삼는다. 애니메이션이 끝나거나 다른 행동을 실행했을 때 원래 자리로 돌아가지 않는다. 최신 승인 목업에서는 이동한 펫이 그 자리에 머물며, 새로운 이동 행동이 있을 때 위치를 갱신한다. 이동 대상과 두 화면의 최종 위치를 함께 갱신한다. 화면 밖으로 사라지거나 클릭할 수 없는 위치에 놓이지 않아야 한다.

작성자 판단: 이동 위치는 현재 세션에서 유지한다. 앱 종료 후 복원, 장기적인 공간 꾸미기, 가구 배치는 초기 요구에 포함하지 않는다. 여러 행동의 동시 요청, 화면 경계, busy로 전환되는 도중의 행동은 두 화면의 상태가 같게 남도록 처리한다. 연출 중 새 요청을 어떻게 합치거나 제한할지는 구현자가 정한다.

선물은 마음을 전하는 소품이다. 캐릭터 능력치, 실제 생산성 점수, 유료 재화나 성장 수치를 올리지 않는다. 쌓인 소품의 표시 수, 정리 방법 등은 구현자가 화면을 가리지 않는 범위에서 정한다.

## busy

사용자가 직접 켜고 끈다. 안경을 쓰거나 작은 책상에 앉는 모습과 busy 표시로 상태를 드러낸다. 펫은 현재 위치에서 움직임을 멈춘다.

busy 중에는 장난이 통하지 않는다. 장난을 나중에 몰아서 실행하기 위해 예약하지 않는다. 보내는 쪽에서도 현재 상태와 실행할 수 없는 행동을 알 수 있어야 한다.

커피, 에너지음료와 쪽지는 펫 옆에 조용히 쌓인다. 집중을 깨는 수신 애니메이션이나 자동으로 열리는 쪽지 창을 만들지 않는다. 사용자가 직접 확인할 수 있다.

작성자 판단: busy를 풀어도 쌓인 장난을 재생하거나 선물·쪽지를 한꺼번에 자동 개봉하지 않는다. 받은 것을 직접 살펴보는 방식을 유지한다.

## WIP와 쪽지

WIP는 지금 하는 일을 공유하는 짧은 메모다. ‘알고리즘 과제’, ‘OO프로젝트 UX 점검’ 같은 내용을 적는다. 제목은 WIP를 사용하며, main()이나 함수 호출을 전체 UI에 적용하지 않는다.

업무 배정, 마감일, 완료율, 공부 시간 집계는 포함하지 않는다. 작성자 판단: 자유로운 짧은 메모 하나로 시작하고 자기 메모만 수정하게 한다. 정확한 글자 수는 구현자가 정한다. 최신 목업은 WIP 80자, 쪽지 120자로 제한했으며 이는 목업용 값이다.

쪽지는 두 사람이 동시에 접속해 있을 때만 보낼 수 있다. 상대가 offline이면 보내기를 막고 현재 상태를 알려준다. offline 발송 예약이나 다음 접속 때 전달하는 우편함은 만들지 않는다. 상대가 busy이면 받은 쪽지를 선물처럼 옆에 쌓는다.

작성자 판단: 긴 채팅 기록, 검색, 읽음 표시, 답장 스레드는 초기 범위에 넣지 않는다. 이미 전달받은 쪽지의 짧은 보관 방식과 앱 종료 시 정리 방식은 구현자가 결정하되, offline 발송 기능으로 넓히거나 장기 기록 제품으로 바꾸지 않는다. 일시적인 연결 끊김 때문에 이미 확인 가능한 쪽지가 갑자기 사라지는 동작은 피한다.

## 세계관과 문구

컴퓨터 안에 사는 작은 데몬들이 같은 세션에 접속해 함께 밤을 보낸다. 펫은 서로에게 장난스럽고, 커피나 담요를 건넬 때는 다정하며, busy일 때는 제법 진지하다.

| 기능 | 세계 안에서의 표현 |
| --- | --- |
| 함께 있기 | 같은 세션에 접속 |
| 작업 메모 | WIP |
| 가볍게 건드리기 | ping 보내기 |
| 집중 모습 | busy |

문구는 개발 감성이 살짝 묻어나고, 무심한 듯 다정하며 읽으면 피식 웃게 되는 톤이다. 소품만 소재로 제한하지 않는다. 시간대, 잠, 작업 중의 작은 사건, 컴퓨터의 버릇도 쓴다. 모든 버튼을 코드 문법으로 바꾸거나 모든 문장을 쉬운 일상 표현으로 바꾸는 두 방향 모두 사용자가 원한 톤에서 벗어난다.

예시:

- ‘친구는 나갔지만, 커피는 두고 갔어요.’
- ‘담요를 덮었어요. 귀 두 개는 덮이지 않았네요.’
- ‘종이비행기가 도착했어요. 착륙장은 친구 머리였어요.’
- ‘에너지음료를 마셨어요. 발이 조금 바빠졌네요.’
- 아침 상황: ‘해가 떴네요. 이제 슬슬 자러 가요.’

같은 상황에도 여러 문구 중 하나가 랜덤으로 나온다. 사건의 의미와 말투는 유지한다. 바로 전에 같은 상황에서 사용한 문구는 피한다. 동작과 함께 보이는 펫 말풍선도 랜덤으로 바뀌며, 한 사건의 선택 결과는 두 화면에서 같다.

최신 목업의 커피 말풍선: ‘한 모금만’, ‘이 잔은 내 거’, ‘눈이 좀 떠지네’, ‘따뜻할 때 마실게’, ‘커피 옆에 살래’.

최신 목업의 에너지음료 말풍선: ‘아직 할 수 있어’, ‘발이 먼저 깼어’, ‘잠깐, 너무 빨라’, ‘한 캔만 더 버틴다’, ‘지금은 잠이 offline’.

문구의 소재는 넓게 쓰되 실제 접속 여부, busy 여부, 메시지 전달 성공 여부를 혼동시키지 않는다. 상황 안내와 펫의 농담을 구분할 수 있어야 한다. 새벽에 자주 쓰는 서비스지만 낮 시간의 사용도 막지 않는다.

## 비목표와 피해야 할 결과

확인된 제외 항목은 직접 드래그해서 친구 펫을 옮기거나 머리 위에 올려두기, offline 쪽지 발송이다.

초기 기획안에서 제외하기로 제안하고 사용자가 전체 방향을 수용한 항목은 다인원 방, 음성·영상 통화, 업무 배정·마감 관리, 공부 시간 경쟁, 펫 육성·재화 시스템, Windows 및 다른 Linux 환경의 초기 지원이다.

기술적으로 작동해도 다음과 같으면 핵심 가치에 실패한다.

- 펫이 작업창의 입력을 가로채거나 중요한 화면을 계속 가린다.
- busy인 친구에게 장난이 도착하거나, 쌓인 알림이 집중을 반복해서 끊는다.
- 두 사람이 서로 다른 장면이나 문구를 보아 같은 사건을 경험하지 못한다.
- 친구가 실제로 나갔는데 계속 함께 있는 것처럼 보인다.
- 대화, 응답, 접속 유지, 펫 돌보기를 의무처럼 느끼게 한다.
- 개발 용어가 장식으로 과해져 행동을 이해하기 어렵거나, 생활감이 사라진다.

## 구현자가 결정할 사항과 검증

기술 스택, 서버·호스팅, 최초 연결 수단, 설치·업데이트 경로, 소품 정리 방식, 이벤트 충돌 처리, 접근성의 구체적인 조작 방법은 구현 계획에서 결정한다. 선택은 위의 경험과 비공개 일대일 연결을 유지해야 한다. 계정·기기 식별과 연결을 해제하는 수단, 입력 검증, 전송 보호 등 필요한 보안·개인정보 보호를 생략하지 않는다. 화면 내용, 입력 내역, 실행 중인 프로젝트를 수집할 필요는 없다.

움직임 줄이기와 키보드 조작을 제공한다. 움직임을 줄여도 위치 이동 결과, 수신 여부, busy 상태를 이해할 수 있어야 한다. 소리는 초기 기본값에서 요구하지 않는다.

먼저 실제 macOS와 전달받은 KDE Wayland 환경에서 투명 하단 오버레이, 클릭 통과, 포커스 보존, 125% 배율을 검증한다. 그 결과를 근거로 구현 경로를 정하고, 해결되지 않은 플랫폼 제약을 제품이 지원하는 것처럼 표시하지 않는다.

제품 동작 검증에는 일대일 연결의 재사용, 양쪽의 같은 사건·말풍선·최종 위치, busy 중 장난 거부와 선물·쪽지 대기, offline 발송 거부, WIP의 수정 권한, 이동 후 위치 유지, 연결 복구 시 중복 실행 방지를 포함한다.

## 승인 목업과 현재 한계

최신 승인 목업은 프로젝트 루트 기준 `docs/mockups/shared-session.html`에 보존한다. 로컬 v4 시안과 같은 내용이며 이전 버전 대신 이 파일을 동작 참고로 사용한다.

목업은 한 브라우저 탭에서 두 화면과 공유 상태를 재현한다. WIP, 장난, 선물, 쪽지, busy, offline 전환, 혼자 펫 보기, 랜덤 문구, 이동 위치 유지를 체험할 수 있다. 실제 두 컴퓨터의 연결, OS 오버레이, 저장, 최초 연결 절차는 구현하지 않았다. 펫 그래픽과 메뉴 배치는 임시 시안이며, 승인된 경험을 보존하는 범위에서 다듬을 수 있다.

리포는 `leesomin7747/daemon-session`으로 정했다. 기획서, 구현 계획, 승인 목업과 기본 개발 설정을 첫 커밋으로 보존하며, 실제 앱 구현과 의존성 설치는 다음 단계다.
