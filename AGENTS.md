# Project working rules

- Make the smallest complete change that satisfies the request.
- Reuse existing project code, platform features, and dependencies before adding new abstractions or packages.
- Do not introduce speculative architecture or unrequested features.
- Test non-trivial behavior and reproduce bugs before fixing them.
- Never reduce input validation, error handling, security, privacy, or accessibility to save time or code.
- Keep skills task-scoped: use Superpowers for process, Impeccable for intentional UI work, the Vercel React skill for React/Next.js performance, and the web design guidelines for UI review.
- Do not enable or trust lifecycle hooks unless the user explicitly reviews and approves the exact hook definition.
